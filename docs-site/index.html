Untrue: documentation

How the game works, from world generation to the living world.

Untrue is an endless 2D procedural survival and exploration game for the browser. The world is generated around the player in chunks and thrown away behind them, so places can come back different on a later visit. It looks and feels like Stardew Valley: top-down pixel art with a warm, cozy tone. The player is an adventurer who explores, gathers, crafts and fights, but never builds. Every structure is forgotten once the player leaves it far behind. Since rifts tore open all over it, the world has been forgetting itself; stepping through one leads into an outer dimension of challenges (story.md, dimensions.md).

Running it#

Command What it does
npm install Installs dependencies (PixiJS, Vite, TypeScript, Vitest).
npm run dev Starts the Vite dev server.
npm test Runs the Vitest suites once.
npm run build Type-checks with tsc --noEmit, then builds to dist/.
npm run preview Serves the production build.
npm run docs Builds this documentation as a website in docs-site/; open docs-site/index.html.
npm run bake Bakes the outer dimensions' fixed maps into public/dimensions/ (dimensions.md); run when a map's design changes, and commit the result.

Controls#

Input Action
WASD or arrow keys Move
Shift Run (uses stamina)
Left click or J Attack (toward the mouse, or the way you face)
Right click (hold) or K (hold) Block
Space Dodge roll (not while swimming); advances a story vision
E Talk, read, gather, open, drink, rest, enter a building or a rift (or step back out of one), take the stairs, read a lore stone, open a dimension's vault; advances a story vision
1 to 8 Select a hotbar slot
F Use the selected item
Q Drop the selected hotbar stack
Tab or I Open or close the menu
M Open or close the map, where maps work: only inside an outer dimension (the overworld won't hold still)
B The Drift Beacon: public or private rift trips, who is with you behind a rift, the open instances ahead, your name (dimensions.md); opening your world to friends by its code, or visiting a friend's (multiplayer-plan.md)
Escape Close a dialog or the menu; otherwise pause
Ctrl+S Save now
Mouse wheel, + and − Zoom
F3 Debug overlay
G, then H Debug, development builds only: jump 20,000 tiles east, then come back home

Changing keys. On desktop, Settings → Keys lists each action with its main key. Click one, then press the new key (Esc cancels). A key does one thing: if another action had it, that action gets the old key back. "Reset keys" restores the defaults. The arrow keys, right Shift, I (bag) and the numpad + and − always work too. Esc, F3, F4 and 1–8 are kept for the game and cannot be bound. Keys are physical positions (KeyboardEvent.code), so WASD sits in the same place on any layout. The controls bar, the pause menu and the tips name the player's own keys. Code: src/game/Keys.ts.

Touch screens get:

  • a virtual stick (drag on the left half of the game; a faint one rests bottom left),
  • tap-to-interact (a quick tap anywhere on the game, or on the action prompt, acts like E),
  • pinch to zoom: two fingers together zoom instead of steering (the second finger counts as a pinch if it lands within 250 ms of the first, or if the first is not steering),
  • Use, Bag, Hit, Roll and hold-to-Block buttons; Hit aims at the nearest enemy in reach,
  • small Beacon, Pause and Full buttons above the action buttons (Beacon opens the Drift Beacon's panel),
  • the Full button is full screen (also in the pause menu). iPhones have no full screen for pages, so the button is hidden there; Add to Home Screen opens the game full screen instead (public/manifest.webmanifest).

Tapping a hotbar slot selects it and shows the item's name (and a weapon's durability) above the bar for a moment; tapping it again uses it. On touch screens the vitals sit under the compass and the buttons bottom right, and the pause menu lists the touch controls.

URL parameters#

Parameter Effect
?new Start a new world with a random seed, ignoring the save.
?seed=N Start a new world with seed N, ignoring the save.
?spawn=x,y Spawn at tile x,y (development builds only).
?hour=H Set the clock to hour H (development builds only).
?weather=kind Force a weather kind in every biome for 24 hours (development builds only): clear, rain, storm, fog, sandstorm, heat, snow, blizzard.
?vitals=N Start health, stamina, hunger and thirst at N% (development builds only), to see the low warnings.
?playground or ?playground=SEED Story playground (development builds only): a fresh world, never saved, with a panel (F4 or tapping its title folds it) to travel to the spawn, set night or morning, toggle god mode and restart, and for the rifts: tear one open nearby, enter The Hollow (alone, or shared: through the rift's passage into a shared instance), and go to its Glitch Nest, Crumbling Path or Glyph Hall, or to the Warden or the vault with what bars the way done.
?fps=30 Cap the frame rate at 30 (it is otherwise capped at 60).
?net=local Testing multiplayer on one machine: tabs of this browser find each other (over a BroadcastChannel) instead of strangers on public relays, and each tab is a new player. Shared rift trips: open two or three windows of ?playground&net=local and press "Enter the Hollow (shared)" in each. Visiting a world: in one window of ?playground&net=local open the Drift Beacon (B), press "Open my world" and read the code; in another window open ?join=CODE&net=local (or type the code into its beacon), then let them in on the first.
?join=CODE Visit the world with this code (what the beacon's Visit button does). The visitor's own world is saved and set aside; going home (the beacon's "Go home", or the host closing their world) brings them back to it.

The game strips the query string after reading it, so reloading continues the same world.

In dev builds (npm run dev), the running game is available in the browser console as window.game.

Deploying#

npm run build writes a static site to dist/: upload the folder to any static host (Netlify, GitHub Pages, itch.io, an S3 bucket, nginx). Paths are relative, so it works from a subfolder too. The game code (about 100 KB gzipped) and Pixi (about 160 KB gzipped) are separate files, so players keep Pixi cached across updates; serve dist/assets/ with long cache headers, since its file names change with every build. Pixi's WebGPU code ships inside the Pixi file even though the game uses WebGL: Pixi's main export imports it statically, so splitting it out would need a custom Pixi build, and vite.config.ts does not try.

On Vercel: import the project (or run vercel in its folder). vercel.json already sets everything: npm ci, npm run build, output dist/, a year of immutable caching for dist/assets/, and a few safe security headers. Node 22.12 or newer is required (engines in package.json; Vercel's default Node 22 is fine). No environment variables or server functions are needed: the game is entirely static, and saves stay in each player's browser. Playing alone makes no outside requests; a public rift trip (the Drift Beacon's default) reaches public Nostr relays (to find others) and public STUN servers (to link to them), listed in the CSP's connect-src, and the multiplayer code (about 35 KB gzipped) is a separate file loaded only then. The Pixelify Sans font ships with the game (@fontsource/pixelify-sans, imported at the top of src/style.css so the opening screen has it from the first paint), so no player data reaches Google Fonts.

What keeps a live build safe:

  • Saves live in IndexedDB in the player's browser. If storage is blocked (some private modes), the game still runs and says once that it cannot save. A save that cannot be read (for example, one from a newer version) is kept as a backup and a new world begins, with an alert, instead of the game failing to start. If storage fails to read at all, that session does not save, so it cannot overwrite a save it never saw. Older save versions are upgraded. See saves.md.
  • World generation runs in web workers, and falls back to the main thread if workers cannot start or one fails, so the world always loads.
  • Errors in a frame are logged and the game carries on (Pixi would otherwise stop ticking). If the game cannot start at all (no WebGL), the page says so.
  • Cheats are off: ?spawn, ?hour, ?weather, the G/H teleport and window.game only exist in development builds. ?seed, ?new, ?fps=30 and ?net=local work everywhere.
  • Others behind the rifts cannot reach a player's overworld or save: a guest's blows are requests the host checks (reach, rate, strength), every message is bounds-checked and malformed ones are dropped, and peers on another game version or with a different map are refused. See networking.md.
  • Two tabs: only the first tab saves (a Web Lock, with a BroadcastChannel fallback); a later tab plays without saving and says so.
  • Touch screens get a left-half stick, tap-to-interact, pinch zoom, a tappable action prompt, Use, Bag, Hit, Roll, hold-to-Block, Beacon, Pause and Full buttons, and a layout that fits phones upright or sideways.
  • Accessibility: screen flashes can be turned off (and are off by default under the system's reduced-motion setting, which also stops HUD animation), the text and HUD size runs from 0.8 to 1.5, desktop keys can be changed, and first-time tips explain each part of the game as it comes up.

Privacy and licenses#

  • No personal data: no accounts, analytics, ads or cookies. Saves (IndexedDB) and settings (localStorage) stay in the player's browser, which counts as strictly necessary storage, so no consent banner is needed. The host's server logs (Vercel) are the only data anyone else sees while playing alone. Meeting others behind a rift links players' browsers directly, so each sees the others' IP addresses (as in any peer-to-peer game), and the public relays see the board's notes (a name, a dimension, a join code) and encrypted signaling; a random key, kept in localStorage, is the only identity. Private rift trips (the beacon) avoid all of it.
  • About tab (beside Settings in the menu, src/ui/About.ts): a short privacy note, credits (original art and sound) and the open source licenses, with the full texts on demand.
  • Third-party notices: npm run build first runs scripts/build-notices.mjs (also npm run notices), which writes the license of every shipped package (Pixi.js and its dependencies, Pixelify Sans under the SIL OFL 1.1) to public/THIRD_PARTY_NOTICES.txt. Type-only packages are skipped.
  • Before the app stores, analytics, ads, accounts or sales: the stores want a privacy policy URL; tracking needs a full privacy policy and consent; selling needs a trademark check on the name.
